一款适用于 Cloudflare WARP 的 Windows 客户端，它能够扫描最佳端点，并通过一键连接——基于 的 vernette/warpscout扫描引擎构建，并嵌入了 Clash (mihomo) 核心，用于实际的流量路由。

下载： 最新版本 ——将便携式软件包解压到任意可写位置并双击运行 xehn.exe。该软件包不包含任何账户：首次连接会为该机器注册一个新的 WARP 设备。

许可证通知和遥控器
每次启动时都会弹出许可提醒，要求所有构建版本都必须携带此许可——本软件开源免费，仅供学习交流使用，禁止售卖！ ——同样的句子也保留在“关于”页面底部，即使关闭通知后仍然可见。“关于”页面本身并不指向本地：每一行和每一个按钮都会打开一个 GitHub 地址（项目页面、发布版本、问题、通知、许可文本、核心源代码），因为对于在其他机器上阅读此页面的用户来说，指向本地磁盘上的路径毫无意义。

每次安装都会携带一个控制代码（XXXX-XXXX-XXXX-XXXX可在“关于”菜单中显示和复制），该代码源自计算机的 Windows 标识——因此删除 settings.json不会生成新的控制代码。客户端 control.json在启动时以及之后每隔 15 分钟从默认分支读取数据：

{
  "stop_all": false,
  "stopped_codes": ["ABCD-EFGH-JKMN-PQRS"],
  "message": ""
}
列出的代码（或stop_all）会阻止该客户端：它拒绝连接，断开已建立的会话，并在屏幕上显示原因。message这会替换默认语句。此检查特意采用失败开放机制：不可达列表会保留之前的判定结果，因此离线的笔记本电脑或阻塞的 GitHub 不会破坏合法的安装，同时判定结果会被缓存，control-state.json 因此重启不会悄悄地将已停止的客户端恢复到服务状态。

客户引入的两个“核心”
AWG 核心—— amneziawg-go（已经是 warpscout 的依赖项）。它是用户空间的 AmneziaWG 实现，既用于扫描（验证端点是否确实存在于其声称的位置），也作为 mihomo 代理渲染的基础。
Clash 核心——mihomo（MetaCubeX/mihomo），以边车二进制文件的形式运行。所有成熟的 Clash 图形用户界面（Clash Verge、FlClash 等）都采用相同的模式：客户端编写完整的配置文件config.yaml，启动核心，通过external-controllerREST API 控制它，并将操作系统指向其混合端口。mihomo 原生支持wireguard(+ amnezia-wg-option)、masque (+ network: h2) 和dialer-proxy链式调用，因此单个嵌入式核心即可覆盖所有四种协议以及用于路由的 WARP-in-WARP。

-H windowsgui它会移除控制台子系统标志，因此双击不会弹出终端窗口。同一个二进制文件仍然为命令行界面 (CLI) 提供服务：它通过一个子命令连接到调用者的控制台并重新打开其标准流。如果没有连接控制台，图形用户界面 (GUI) 会将所有输出（包括它自身的输出和 mihomo 核心的输出）重定向到xehn.logexe 文件旁边。由于 Windows 不会等待 GUI 子系统进程完成，cmd因此会立即返回到其提示符，而 register/connect 命令则在后台继续运行；它们的输出会一直连接到该终端。

用法
# 0. no arguments at all → the native GUI window (double-click equivalent)
xehn.exe
xehn.exe gui      # force the native window

# 1. register a WARP account
xehn register

# 2. connect — scans (cached 6h), picks best endpoint, starts core, sets proxy
xehn connect -p awg
xehn connect -p wg
xehn connect -p masque
xehn connect -p masque-h2
xehn connect --tun            # TUN global mode (needs admin)
xehn connect --scan-now       # force re-scan, ignore cache
xehn connect -p awg --psiphon # base protocol + Psiphon exit (final IP = Psiphon)

# 3. show current exit IP / latency / country
xehn status

# 4. list cached endpoints
xehn list
xehn list -p wg

# 5. disconnect — stops core, restores prior system-proxy state
xehn disconnect

# raw engine commands (from warpscout) still work:
xehn scan -best -p awg
xehn scan -conf - -conf-type mihomo -p awg
便携式/定制住宅
如果WARP_CLIENT_HOME未设置，客户端会自动将其主目录锚定到可执行文件的文件夹（如果可写，例如解压后的 ZIP 文件），否则回退到 %APPDATA%\xehn默认目录。要将其固定到默认目录，请显式设置该变量：

$env:WARP_CLIENT_HOME='D:\warp-portable'
xehn connect
虹吸出口（V1）
Psiphon 是一个出口，而不是第五个协议。connect --psiphon它首先启动基础协议（WG/AWG/MASQUE），将 Psiphon 的上游指向该本地主机 SOCKS，并将 Psiphon 作为最终出口——因此公共出口 IP 变为 Psiphon 的 IP。会话是一个组合：status例如，显示session=AWG-Psiphon，而state.Proto保持基础协议（awg），交换机位于 psiphon_mode。

资产——两者都是必需的；connect --psiphon如果缺少其中任何一项，系统都会快速报错并显示明确的错误信息：

资产	默认位置	覆盖
Psiphon 可执行文件	core\psiphon.exe	--psiphon-exe标志，否则PSIPHON_EXE环境
官方客户端配置	core\client.config， 然后core\psiphon.config	PSIPHON_CONFIG环境
客户端配置包含SponsorId/ PropagationChannelId/ RemoteServerListURLs/ObfuscatedServerListRootURLs及其签名密钥——如果没有这些密钥，Psiphon 将无法发现任何服务器，也永远不会建立隧道。 server_list.dat旁边的 / 用作初始服务器列表。

xehn connect -p awg --psiphon
xehn status            # session=AWG-Psiphon  endpoint=…  exit=<Psiphon exit IP>
